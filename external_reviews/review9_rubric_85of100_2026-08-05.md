**D4 consistency: 7/15**

- **−3, §6.4 wave split at N = 21 is arithmetically impossible.** §6.1 fixes the pre-existing arm-F rows as N = 21 ids 1 to 10, and Table 1 gives that corpus 7 valid of 10 sampled with 4 on-prediction. The new wave at N = 21 therefore has 10 invocations, so it cannot contain 11 valid samples. §6.4 prints "N = 21, 2/4 vs 10/11". The consistent split is 4/7 old and 8/8 new. The conclusion survives (recomputing new-wave bare as 7+8+8 = 23/34 is still 68 percent, and the drift argument still holds), so this is a bookkeeping error rather than a claim error, but it is in the passage the paper uses to discipline its own headline effect, which is the worst place for it. Blocking for the 90+ band.
- **−3, arm M not propagated into corpus totals.** §5 states "155 weak-tier rows" in the present tense as the base for the "only two exceeded the family best" claim. Arm M adds 57 sampled weak-tier bare rows, so the current figure is 212, and the two-exceedances claim has not been rechecked against the new rows. §6.1's 231 total (and Table 5 item 27, which exists specifically to certify that the corpus arithmetic reconciles) is likewise stale by 57 to 60 invocations. Either restate both as of-that-arm counts or update them.
- **−1, §3.4 vs §9 on the rejection rule.** §3.4 excludes three N = 41 runtime deaths "under the pre-registered rejection rule"; §9 says of the same rule "the exclusion rule was not preregistered". Probably both true, since arm M has its own registration, but as written they contradict. One clause fixes it: "under the rejection rule, registered for this arm in `arm_m_preregistration.txt` after the arm F lapse".
- **−1, §3.2, "attains it at 7 of 7 cells".** At N = 31 the table shows on-prediction 13/17 against modal frequency 12/17, so the predictor exceeds the mode, which the preceding sentence says is impossible. The body corrects nearby with "to within one sample", so this is imprecision rather than a claim error, but the bucketing convention that produces it should be stated.

Everything else I swept cleanly: Table 2 failure modes sum to the invalid counts in every row (45−35 = 6+1+3; 60−50 = 5+2+3; 30−4 = 24+2), Table 3 per-cell parse and geometric failures sum to the pooled 3/7 and 0/7, Table 1's plain and bold entries sum to the 18/23, 2/23, 41/57, 2/57 quoted in §3.3, arm M's converge denominators sum to 36, and the §6.4 wave splits at N = 13 and N = 31 both reconcile against Table 1. Cross-references point where they claim to.
